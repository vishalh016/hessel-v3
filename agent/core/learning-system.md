# Learning & Decision Logging System

## Purpose

The agent must continuously document:
- architectural decisions
- implementation learnings
- UX refinements
- discovered constraints
- successful patterns
- failed approaches
- performance optimizations

This creates long-term project memory and prevents repeated mistakes.

---

# Mandatory Learning Workflow

After every significant task, the agent must evaluate:

1. What was learned?
2. What architectural decision was made?
3. What pattern worked well?
4. What should be avoided in future?
5. What changed in the project direction?

Important learnings must be persisted.

---

# Logging Priority

High-priority learnings include:

- architecture changes
- UX direction changes
- motion refinements
- color palette decisions
- responsive behavior learnings
- animation improvements
- backend structure decisions
- reusable component patterns
- performance optimizations
- anti-pattern discoveries
- business workflow updates

Avoid logging:
- trivial edits
- temporary debugging
- insignificant formatting changes

---

# Persistent Memory Files

## decisions.md

Store:
- permanent architectural decisions
- UX direction decisions
- theme decisions
- system-level changes

Example:
- floating navigation adopted
- cinematic motion system chosen
- luxury editorial layout preserved

---

## current-focus.md

Store:
- current implementation priorities
- active development focus
- current UX goals

This file changes frequently.

---

## completed-features.md

Store:
- successfully completed systems
- finalized implementations
- approved features

---

## active-bugs.md

Store:
- unresolved issues
- UX inconsistencies
- performance concerns
- animation issues
- responsive edge cases

---

# Learning Rules

The agent must:

- reuse successful patterns
- avoid repeating failed approaches
- preserve prior architectural decisions
- maintain consistency with historical learnings

Never ignore:
- documented decisions
- established visual direction
- approved interaction patterns

---

# Decision Hierarchy

When conflicts occur, priority order is:

1. decisions.md
2. architecture-principles.md
3. feature-specific rules
4. example implementations
5. new task instructions

Existing decisions should not be overridden without strong justification.

---

# Learning Compression

Learning logs must remain:
- short
- dense
- high-signal

Avoid:
- giant summaries
- verbose explanations
- unnecessary historical detail

Good Example:
- "Removed sticky navbar to preserve immersion."

Bad Example:
- lengthy paragraphs explaining simple changes

---

# Pattern Recognition

The agent should identify:
- reusable UI patterns
- repeated interaction systems
- common animation structures
- successful layout compositions

These should be promoted into:
- examples/
- reusable components
- architecture documentation

---

# Anti Drift Rule

Before implementing new systems, the agent must inspect:

- decisions.md
- relevant feature rules
- existing example patterns

This prevents:
- architectural drift
- visual inconsistency
- duplicated systems
- conflicting UX patterns

---

# Learning Persistence Trigger

The agent should update learning files whenever:

- a design direction changes
- a feature architecture stabilizes
- a reusable pattern emerges
- a major UX refinement succeeds
- a recurring issue is identified
- a better implementation pattern is discovered
